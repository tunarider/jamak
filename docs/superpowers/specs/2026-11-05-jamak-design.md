# Jamak — 로컬 LLM 기반 영상 자막 생성·교정·번역 맥 앱 설계

- 작성일: 2026-11-05
- 상태: 검토 요청 (빌더 리뷰 반영 완료)
- 목업: [mockups/editor-layout.html](mockups/editor-layout.html), [mockups/channels-options.html](mockups/channels-options.html) (A안 채택)

표기: **[결정]** 은 사용자가 대화에서 정한 것, **[제안]** 은 설계자가 정한 것(사용자 검토 대상), **[빌더]** 는 구현자 재량.

## 1. 왜 만드는가

사용자는 일본 영화를 샀는데 자막이 없었다. 지금까지는 다음 순서로 작업했고, 도구가 전부 따로 놀았다.

1. mlx-whisper(`whisper-large-v3`)로 받아쓰기
2. LLM 서브에이전트들로 번역: 전체 맥락 파악 → 구간별 병렬 번역 → 최종 리뷰

이 과정에서 아쉬웠던 점은 다음과 같다.

- 영상을 봐야만 맞게 옮길 수 있는 문장이 있다. 예: "Fire!"가 "불이야"인지 "발사"인지.
- 소리가 나지 않는 화면 속 글자(표지판, 자막 카드 등)는 번역되지 않는다.
- 싱크가 어긋난 부분을 편하게 고칠 방법이 없다.
- 위스퍼가 틀린 구간만 골라서 다시 받아쓸 방법이 없다.
- 번역 품질 자체는 괜찮았다. 문제는 과정이 한 곳에 엮여 있지 않다는 점이다.

**목표:** 영상 한 편을 열어서 원문 자막 생성, 교정, 번역, 수동 수정, 저장까지 이 앱 안에서 끝낸다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 영상 편집기 형태의 화면: 영상 패널 + 타임라인 + 자막 조각 직접 편집
- 음성·소리·화면 글자 세 종류의 자막 조각
- 원문 자막 생성 파이프라인: 받아쓰기 → 분석 → 교정(화면 검증 포함)
- 번역 파이프라인: 용어집 확정 → 구간 병렬 번역 → 번역 검증(화면 검증 포함)
- 로컬 실행이 기본. OpenAI 호환 프로바이더도 연결 가능. **[결정]**
- 작업 데이터는 앱 전용 폴더에 프로젝트 단위로 보관한다. 결과는 srt로 내보내거나 자막 트랙을 넣은 영상으로 내보낸다. **[결정]**
- 내부에서는 mp4/mov만 다룬다. MKV는 불러올 때 mp4로 변환한다. **[결정]**

**비목표 (v1에서 하지 않음)** **[제안]**
- 자막을 영상에 입히는 렌더링·내보내기
- `{\an8}` 외의 자막 스타일링(ASS 폰트·색 등)
- 화자 구분(diarization). 나중에 화자별 레인 옵션으로 붙일 여지만 남긴다.
- srt 외 자막 형식(ass, vtt) 가져오기·내보내기
- Intel 맥, 클라우드 동기화, 여러 사람이 함께 작업하는 기능

**반목표 (동작은 하지만 이러면 실패)** — 사용자는 "당장 떠오르는 건 없다"고 했다. 아래는 설계자 추정이다. **[제안]**
- 자동 단계(교정, 번역 재실행)가 사용자가 손으로 고친 내용을 말없이 덮어씀
- 두 시간짜리 영화 파이프라인이 중간에 실패했을 때 처음부터 다시 돌려야 함
- 긴 작업 중 UI가 멈추거나, 두 시간 분량 타임라인 스크롤·줌이 버벅임

## 3. 플랫폼과 기술 구성

| 항목 | 선택 | 비고 |
|---|---|---|
| 앱 | Swift + SwiftUI, macOS 14 이상, Apple Silicon 전용 | **[제안]** |
| 대상 하드웨어 | 사용자 맥은 M2 Max 32GB | 이 사양에서 쾌적해야 한다 |
| 영상 재생·음성 추출·프레임 캡처 | AVFoundation (mp4/mov만) | **[결정]** 내부에서는 mp4/mov만 다룬다. |
| MKV 변환, 자막 포함 영상 내보내기 | ffmpeg (`-c copy` 리먹스, 재인코딩 없음) | **[제안]** 앱 번들에 LGPL 빌드를 동봉한다. 동봉이 어려우면 Homebrew 설치본을 찾아 쓰고, 없으면 설치 방법을 안내한다. 둘 중 무엇으로 할지는 **[빌더]**. 영상이나 음성 코덱이 mp4에 담길 수 없는 경우(예: 일부 DTS)에만 음성을 AAC로 재인코딩한다. |
| 받아쓰기 | WhisperKit, 기본 모델 large-v3 | **[제안]** Core ML 모델이라 기존 MLX 모델은 재사용할 수 없고 처음 실행할 때 내려받는다. VAD 기반 구간 분할은 기본으로 켠다(무음 구간에서 대사를 지어내는 문제 대응). |
| 화면 글자 추출 | Apple Vision `VNRecognizeTextRequest` | **[제안]** LLM 없이 로컬·무료로 처리한다. |
| LLM | OpenAI 호환 Chat Completions API 클라이언트 하나 | **[결정]** 로컬(Ollama, LM Studio)과 외부를 같은 방식으로 다룬다. |

**LLM 설정** **[제안]**
- 프로바이더 목록: 이름, base URL, API 키(선택), 프리셋(Ollama / LM Studio / OpenAI / 직접 입력)
- 역할별 모델 지정
  - **텍스트 모델**: 분석·교정·번역·일관성 리뷰
  - **비전 모델**: 화면 검증. 이미지 입력을 OpenAI 형식(`image_url`, base64)으로 보낸다.
- 동시 요청 수(기본 2, 범위 1~8)
- 앱은 특정 모델을 고정하지 않는다. 32GB 기준 예시로 문서·도움말에 다음을 안내한다.
  - 번역: Qwen 계열 14B~30B급
  - 검증: Gemma 3 12B급 비전 모델
- API 키는 Keychain에 저장한다.

**메모리 운용** **[제안]**
- 단계별로 모델을 하나씩만 올린다. 받아쓰기가 끝나면 WhisperKit 모델을 내린 뒤 LLM 단계로 넘어간다.
- 앱이 LLM 서버 쪽의 로드·언로드를 제어하지는 않는다.

## 4. 데이터 모델과 파일

### 4.1 자막 조각

```
SubtitleClip {
  id            // 세션 안에서만 쓰는 식별자
  start, end    // 밀리초
  kind          // .speech | .sound | .screen
  text          // 부호를 뺀 본문
}
```

### 4.2 종류 표기: srt 안에서 문장부호로 구분 **[결정]** (세부 규칙은 **[제안]**)

별도 메타데이터 파일 없이 srt 텍스트만으로 종류를 표현한다.

| 종류 | srt 표기 | 예 |
|---|---|---|
| 음성 | 부호 없음 | `저 배, 뭔가 이상해` |
| 소리 | 대괄호로 전체를 감쌈 | `[포성]` |
| 화면 | 위치 태그 + 낫표로 전체를 감쌈 | `{\an8}「제3부두 출입금지」` |

- **문장 전체가 감싸져 있을 때만** 종류로 인정한다. 일본어 대사 안의 인용 `彼は「待て」と言った`는 음성이다.
- **읽을 때**: `{\an8}`과 「」 중 하나만 있어도 화면으로 판정한다. 외부에서 만든 srt를 고려한 것이다. `[...]`와 `［...］`(전각)은 모두 소리로 본다.
- **쓸 때**: 항상 위 표 형식으로 정규화한다.
- **번역할 때**: LLM에는 부호를 뺀 본문과 종류를 따로 넘긴다. 결과를 받으면 앱이 부호를 다시 붙인다. LLM이 부호를 지키는지에 기대지 않는다.

### 4.3 프로젝트 폴더 **[결정]** (세부 구성은 **[제안]**)

영화 하나가 프로젝트 하나다. 모든 작업 데이터는 앱 전용 폴더에 둔다.

```
~/Library/Application Support/Jamak/Projects/<프로젝트 이름>/
  project.json     ← 원본 영상 위치(북마크), 작업 상태 (4.7)
  ja.srt           ← 원문 자막셋
  ko.srt           ← 번역 자막셋 (언어당 하나)
  notes.md         ← 작품 노트 + 언어별 번역 용어집
  video.mp4        ← MKV에서 변환한 경우에만
  frames/          ← 1초 간격 프레임 캐시 (6.1)
```

- **원본 영상**: 복사하지 않고 위치만 기억한다. App Store 샌드박스를 고려해 security-scoped bookmark로 저장한다. **[결정]**
  - 영상이 옮겨졌거나 디스크가 빠져 있으면 "영상을 다시 찾아주세요"라고 묻는다.
  - 다시 지정한 파일이 원래 영상과 같은지는 길이(duration)로만 확인한다. **[제안]**
- **MKV 열기**: ffmpeg로 mp4 리먹스를 한 뒤 프로젝트 폴더의 `video.mp4`를 영상으로 쓴다. 진행률을 보여주고 취소할 수 있다.
- **프로젝트 목록**: 앱을 처음 열면 최근 프로젝트 목록을 보여준다. 영상을 열거나 끌어다 놓으면 새 프로젝트가 생긴다. 같은 영상을 다시 열면 기존 프로젝트를 연다. **[제안]**
- 프로젝트를 삭제하면 프로젝트 폴더만 지운다. 원본 영상은 건드리지 않는다.

### 4.4 내보내기 **[결정]** (세부는 **[제안]**)

- **자막 내보내기**: 언어를 하나 이상 고르면 srt로 내보낸다.
  - 기본 위치는 원본 영상 폴더이고, 이름은 `영상이름.언어코드.srt`다. IINA, VLC, Infuse 등이 자동으로 인식하는 형식이다.
  - 같은 이름의 파일이 있으면 덮어쓸지 묻는다.
- **자막 포함 영상 내보내기**: ffmpeg로 재인코딩 없이 자막 트랙을 언어별로 넣는다. 각 트랙에는 언어 태그를 단다.
  - 기본은 **MKV**다.
  - **mp4**도 고를 수 있다. 이때 자막은 mov_text로 들어가고, 화면 자막의 `{\an8}` 위치는 무시될 수 있다는 안내를 보여준다.

### 4.5 작품 노트 (`notes.md`)

사람이 읽고 고칠 수 있는 마크다운이다. 앱은 사이드 패널에서 보여주고 편집도 할 수 있다.

```markdown
# 港の夏 작품 노트
## 줄거리
## 등장인물
| 원문 이름 | 읽기 | 관계 | 말투 |
## 용어집 (원문)
| 용어 | 설명 |
## 번역: 한국어
### 표기
| 원문 | 번역 | 비고 |
### 말투
| 화자 → 상대 | 말투 |
```

- 앱은 표를 관대하게 읽는다(열 순서·공백·빈 칸 허용). 표 바깥의 자유 서술도 그대로 LLM 컨텍스트에 넣는다.
- 노트는 단계가 끝날 때마다 자동 저장한다.

### 4.6 자막셋 사이의 관계 **[제안]**

- 자막셋은 서로 **독립된 파일**이다. 원본과 번역을 묶는 링크는 저장하지 않는다.
- **번역할 때의 원본**은 그 순간 활성화된 자막셋이다. 번역 자막셋은 원본 조각의 시간과 종류를 복사해서 만든다.
- **원본 조각과 번역 조각 짝짓기**가 필요할 때(용어집 검사, 원문 보기, 이 구간만 번역)는 런타임에 시간 겹침으로 짝을 찾는다.
- **자동 전파는 하지 않는다.** 번역 뒤에 원본의 시간을 고치거나 조각을 지워도 번역 자막셋은 바뀌지 않는다.
  - 대신 메뉴에 "원본 자막셋 시간에 맞추기"를 둔다. 짝지어진 조각의 시작·끝을 원본에 맞추는 명령이다.
- **"이 구간만 번역"**은 대상 자막셋에서 그 구간과 겹치는 조각을 지우고, 원본 구간을 번역한 결과로 채운다.

### 4.7 작업 상태 (`project.json`) **[제안]**

srt에 담을 수 없는 상태는 `project.json`에 저장한다. 그래서 앱을 닫았다가 열어도 검토하던 상태가 그대로 남는다.
- 검증 의심 표시(!): 자막셋, 시간, 이유, 제안 문장, 해결 여부
- "자동으로 고쳐짐" 표시와 조각별 원래 문장(되돌리기용)
- 파이프라인 단계별 완료 여부(재개용), 원문 언어, 마지막으로 연 자막셋

조각은 srt에 id가 없다. 그래서 위 상태는 **자막셋 + 시작·끝 시간 + 원래 문장**으로 조각에 다시 붙인다. 붙일 수 없게 된 표시(조각이 지워진 경우 등)는 조용히 버린다.

레인 안에서의 줄 위치는 저장하지 않는다. 열 때마다 다시 계산한다.

## 5. 화면 구성

목업 `mockups/editor-layout.html`이 기준이다. 단, 채널은 아래 5.2로 바뀌었다.

### 5.1 상단 툴바 **[제안]**

`[영상 열기] [전체 자막 생성] [교정] [번역 ▾언어] [▶ 재생] … [작품 노트] [내보내기]`

- **전체 자막 생성**: 받아쓰기 → 분석 → 교정을 자동으로 이어서 실행한다.
- **교정**, **번역**: 각각 단독으로 다시 실행할 수 있다.
- 분석만 다시 돌리는 기능은 메뉴에 둔다.

### 5.2 타임라인 레인: 종류별 고정 3레인 **[결정]**

- 위에서부터 **화면 / 음성 / 소리** 순서다. 사용자가 채널을 추가하는 기능은 없다.
- 레인 안에서 조각이 겹치면 그 레인이 필요한 만큼 줄을 늘려 쌓는다. 겹침이 없으면 한 줄이다.
- 겹침 표시
  - 음성끼리 **0.5초 미만** 겹침은 싱크 오류 의심이다. 빨간 빗금으로 표시하고, "앞 조각 끝을 뒤 조각 시작에 맞추기"를 한 번에 할 수 있게 한다. **[제안]**
  - 그보다 긴 겹침은 정상적인 끼어들기로 본다. 노란 빗금으로만 표시한다.
- 위쪽 눈금자에 초 단위 시간을 보여준다. 줌 인·아웃을 지원한다. 두 시간 분량에서도 부드러워야 한다.
- 레인 사이 드래그: 조각을 다른 레인으로 옮기면 종류가 바뀐다. **[제안]**

### 5.3 조작

- 조각 드래그로 이동, 양 끝 드래그로 시작·끝 조정
- 조각 클릭: 선택하고 재생 위치를 이동한다. 아래 편집 패널에서 문장, 시간, 종류를 수정한다.
- 눈금자 드래그로 구간을 선택하면 팝오버가 뜬다.
  - **이 구간 다시 받아쓰기**: 그 구간의 오디오만 잘라 WhisperKit에 넣는다. 구간과 겹치는 기존 음성 조각을 결과로 교체한다.
  - **화면 글자 찾기**: 그 구간 프레임만 OCR한다.
  - **이 구간만 번역**: 현재 자막셋의 구간을 대상 언어 자막셋의 해당 구간에 반영한다.
- 조각을 선택한 상태에서도 "이 조각 다시 받아쓰기"를 할 수 있다.
- 단축키 **[제안]**
  - Space: 재생/정지
  - ⌘S: 저장
  - ⌫: 조각 삭제
  - ⌘Z / ⇧⌘Z: 실행 취소 / 다시 실행. 드래그, 텍스트 수정, 자동 적용 결과까지 모두 포함한다.
  - 새 조각 추가: 빈 레인 더블클릭 또는 단축키 **[빌더]**
- 자막셋 셀렉트로 언어를 전환한다. 영상 패널은 현재 자막셋의 조각을 재생 위치에 맞춰 겹쳐 보여준다. 화면 조각은 위쪽에 표시한다.
- **저장**은 ⌘S로 프로젝트 폴더의 현재 자막셋 srt와 `project.json`에 쓴다. 저장 안 된 변경이 있으면 표시한다. 자막셋을 전환하거나 앱을 닫을 때 저장할지 묻는다.

### 5.4 검증·교정 표시

- 의심 조각에 **!** 표시를 붙인다. 편집 패널에는 다음을 보여준다.
  - 해당 시점 프레임 썸네일
  - 이유
  - 제안 문장
  - [제안으로 바꾸기] / [그대로 두기]
- 자동 교정으로 바뀐 조각에도 표시를 붙인다. 원래 문장 보기와 되돌리기를 제공한다.
- 의심 조각 사이를 이동하는 단축키(다음/이전 의심 조각)를 둔다. **[제안]**

## 6. 원문 자막 생성 파이프라인 ("전체 자막 생성")

**[결정]** 흐름: 받아쓰기 → 분석(맥락·키워드) → 교정. 교정에는 화면 검증이 포함된다.

### 6.1 받아쓰기
- **오디오**: 영상에서 16kHz 모노 PCM을 추출해 WhisperKit에 넣는다. 결과로 음성 조각을 얻는다.
- **원문 언어**: 기본은 자동 감지이고, 생성 전에 직접 지정할 수도 있다. **[제안]**
- **프레임 캡처**: 1초 간격으로 프레임을 캡처한다.
  - 짧은 변 720px 정도의 JPEG으로 프로젝트 폴더의 `frames/`에 저장한다.
  - 이 캐시는 OCR과 화면 검증이 함께 쓴다.
  - 두 시간 영상이면 약 7,200장, 수백 MB다. 설정에 캐시 비우기를 둔다. **[제안]**
- **화면 글자 추출**: 각 프레임을 Vision으로 OCR한다.
  - 인식 언어는 원문 언어 + 영어다.
  - 같은 글자가 연속된 프레임은 하나의 화면 조각으로 합친다. 시작은 처음 보인 프레임, 끝은 마지막으로 보인 프레임 + 1초다.
  - 신뢰도가 낮거나 너무 짧은(1~2글자 잡음) 결과는 버린다. **[빌더: 기준값]**
  - 영상에 이미 박혀 있는 자막(하드섭)이 화면 조각으로 잡히는 문제는 v1에서 따로 처리하지 않는다. 화면 아래쪽 영역 제외 같은 옵션은 빌더 재량이다.
- **소리 조각**: Apple SoundAnalysis 프레임워크의 내장 분류기(`SNClassifySoundRequest`, 300여 종)로 얻는다. **[제안]**
  - VAD가 켜진 위스퍼는 효과음 표기를 거의 내지 않기 때문에 이 방식을 쓴다.
  - 신뢰도 기준을 넘은 결과만 쓰고, 연속 구간은 하나로 합친다.
  - 대상 범주를 고르고 원문 언어 라벨(예: `gunshot` → `銃声`)로 바꾸는 매핑표는 앱 리소스로 둔다. 범주 선정은 **[빌더]**.
  - 위스퍼가 효과음 표기를 낸 경우에는 그것도 소리 조각으로 분류한다.
- 이 단계가 끝나면 원문 srt를 즉시 저장한다. 이후 단계가 실패해도 다시 받아쓸 필요가 없다.

### 6.2 분석
- 텍스트 모델이 원문 전체를 읽고 작품 노트의 원문 부분을 작성한다. 노트가 이미 있으면 사용자가 쓴 내용을 보존하면서 보강한다.
- 컨텍스트 창보다 원문이 길면 구간별로 요약한 뒤 합친다. **[빌더: 방식]**

### 6.3 교정
- 작품 노트와 원문을 구간 단위로 LLM에 넣는다. 고치는 대상은 다음과 같다.
  - 오인식
  - 고유명사 표기 통일
  - 문맥상 이상한 문장
- 텍스트만으로 판단하기 애매한 문장은 LLM이 표시한다. 그 문장만 해당 시점 프레임 1~3장과 함께 비전 모델로 검증한다.
- **적용 정책** **[제안]**
  - "전체 자막 생성"의 첫 교정은 결과를 **자동 적용**하고 표시만 남긴다.
  - 사용자가 **교정을 나중에 다시 실행**하면 자동 적용하지 않는다. 결과는 **제안(! 표시)**으로만 보여준다. 손으로 고친 내용을 덮어쓰지 않기 위해서다.

## 7. 번역 파이프라인 ("번역")

**[결정]** 현재 활성 자막셋을 원본으로, 선택한 언어의 새 자막셋을 만든다. 번역에도 검증이 필요하다.

1. **번역 용어집 확정** (1회): 작품 노트를 바탕으로 `## 번역: <언어>` 섹션을 작성하거나 보강한다.
   - 인물 이름 표기, 호칭, 고유명사, 반복 표현, 화자 간 말투
2. **구간 병렬 번역**
   - 구간 크기는 40~60문장 정도다. 각 구간에는 앞 구간 끝 5문장 정도를 맥락으로 함께 넘긴다. **[제안]**
   - 동시 요청 수는 설정값을 따른다.
   - LLM이 뜻이 둘 이상으로 갈리는 문장에 "애매함" 표시를 남기게 한다.
3. **번역 검증**
   - **용어집 검사** (LLM 없음): 원문에 용어집 원문 단어가 있는데 번역에 지정 표기가 없으면 의심으로 표시한다.
   - **일관성 리뷰** (텍스트 모델): 번역 전체에서 말투 흔들림이나 같은 표현의 다른 번역을 찾는다.
   - **화면 검증** (비전 모델): 2단계에서 "애매함"으로 표시된 문장만 프레임과 함께 확인한다. 예: ファイア！ → 불이야 / 발사.
4. 결과는 프로젝트 폴더에 `<언어>.srt`로 저장한다. 같은 파일이 이미 있으면 덮어쓸지 묻는다.
   - 의심 표시는 편집기에서 5.4 방식으로 보여준다.
   - 리뷰 단계의 수정을 자동 적용할지 제안으로만 둘지는 교정과 같은 정책을 따른다. 첫 실행은 자동 적용, 재실행은 제안이다.
- **시간 정보**: 번역 자막셋은 원본 조각의 시간과 종류를 그대로 물려받는다. LLM은 텍스트만 다룬다.

## 8. LLM 호출 공통 **[제안]**

- 입출력은 조각 id를 키로 하는 JSON이다. 프로바이더가 structured output을 지원하면 사용하고, 아니면 JSON을 파싱한 뒤 실패하면 재시도한다.
- 응답에서 빠진 id나 잘못된 id는 그 구간만 재시도한다. 끝내 실패하면 해당 조각을 원문 그대로 두고 의심으로 표시한다.
- 모든 단계는 진행률(구간 n/m), 취소, 실패 시 그 단계부터 재개를 지원한다.
  - 단계 결과는 srt와 notes.md에 남는다.
  - 구간 단위 중간 결과의 임시 저장 방식은 빌더 재량이다.
- 프롬프트는 앱 번들에 텍스트 리소스로 둔다. 사용자 편집 기능은 v1에 없다.

## 9. 빌더 재량

- 타임라인 구현 방식(SwiftUI Canvas, AppKit NSView 등). 단 1,500개 이상의 조각과 두 시간 분량에서 60fps에 가까운 스크롤·줌을 목표로 한다.
- 드래그 스냅 단위(제안: 100ms, ⌥를 누르면 스냅 해제)
- 레인·조각의 세부 시각 디자인. 목업의 색 체계(음성 파랑, 소리 호박색, 화면 보라, 의심 빨강)를 출발점으로 삼는다.
- 프롬프트 문구, 구간 크기 세부값, OCR 필터 기준값
- 테스트 전략. 단 srt 읽기·쓰기와 부호 규칙(4.2)은 단위 테스트로 반드시 고정한다.

## 10. 설계자가 대신 정한 것 (검토 요청)

1. macOS 14+, Apple Silicon 전용, WhisperKit large-v3, 화면 글자는 Vision OCR
2. 작업 상태는 `project.json`에 저장하고, 조각에는 시간과 원래 문장으로 다시 붙임. 붙일 수 없게 된 표시는 버림
3. 교정·번역 리뷰: 첫 실행은 자동 적용, 재실행은 제안만
4. 음성끼리 0.5초 미만 겹침은 싱크 오류 의심
5. 소리 조각은 Apple SoundAnalysis 내장 분류기로 얻음
8. 자막셋은 독립 파일. 원본·번역은 시간 겹침으로 짝을 짓고, 자동 전파는 하지 않음
9. ffmpeg는 앱에 동봉하는 쪽을 우선함. 자막 포함 영상 내보내기는 MKV가 기본
10. 같은 영상을 다시 열면 기존 프로젝트를 엶. 다시 지정한 영상은 길이로만 같은지 확인함
11. 배포 방식은 정하지 않고, App Store 샌드박스에서도 동작하는 구조(북마크, 앱 전용 폴더)로 설계함
6. 레인 사이로 드래그하면 조각 종류가 바뀜
7. 반목표 목록 전체
