# 자막 생성·번역·검토 정책과 티켓 설계

- 작성일: 2026-11-07
- 표기: **[결정]**은 사용자가 정한 것, **[제안]**은 설계자가 정한 것(검토 대상), **[빌더]**는 구현자 재량.

## 1. 왜 바꾸는가

자막셋 전체를 번역했는데도 문맥을 놓친 번역이 나왔다. 예시 장면(`japanese_doll_of_terror`, 3:41~3:58):

| 원문 | 번역 | 실제 장면 |
|---|---|---|
| 今度は、朝日撮りに行きたい | 다음엔 일출 찍으러 가고 싶어 | 유리가 마사토에게 일출 찍으러 가자고 조른다 |
| ねえ、朝日 | 있지, 일출 말이야 | "응? 일출 보러 가자~" |
| じゃあ飯をおごるよ | 그럼 내가 밥 살게 | 마사토: "그럼 네가 밥 사" (원문이 おごれよ의 받아쓰기 오류로 보인다) |
| えぇー | 에이 | 유리: 시큰둥 |
| じゃあ無しだな | 그럼 없던 일로 하자 | 마사토: "그럼 (일출은) 없던 걸로" |
| え、ねえお願いお願い | 아, 있잖아, 부탁이야 | 유리: "어? 아냐, 부탁이야 부탁이야" |

원인(코드 기준):
1. 번역은 40~60줄 구간마다 앞 구간의 원문 다섯 줄만 문맥으로 받는다. 구간·조각만 번역하거나 빈 칸만 채울 때는 이웃 줄을 아예 보내지 않는다.
2. 번역 검토는 200줄씩 끊어 말투·용어·표기만 본다. 문맥상 뜻이 틀린 곳은 찾지 않는다.
3. 원문 자체가 틀린 경우(받아쓰기 오류)를 구간·조각 단위로 다시 볼 수단이 없다.
4. 사람이 "이 장면은 이런 상황"이라고 알려 줄 방법이 없다.
5. 생성 작업 안에 교정과 검토가 섞여 자동으로 반영되어, 무엇을 LLM이 바꿨는지 사람이 판단할 자리가 없다.

**반목표** **[제안]**: 다음 중 하나라도 생기면 실패다.
- 검토가 맞는 문장을 취향으로 바꾸고 "고침"으로 반영한다.
- 메모가 내보낸 자막에 섞인다.
- 의심 티켓의 제안이 사용자 승인 없이 내보내기에 들어간다.

**하지 않는 것**
- 기존 프로젝트 호환 **[결정]**: 아직 테스트 단계다. 옛 프로젝트는 지우고 새로 만든다. 옛 형식을 읽는 코드와 표시→티켓 변환은 두지 않는다. 옛 파일을 열면 지금처럼 "열 수 없는 프로젝트"로 보인다.
- 위스퍼 프롬프트 **[결정]**: 장면 설명은 위스퍼에 효과가 없다. 메모는 LLM 작업에만 쓴다.
- 티켓으로 조각 시간을 바꾸거나 조각을 나누고 합치기 **[제안]**: 티켓은 문장만 바꾼다.

## 2. 작업 정책 [결정]

세 가지 작업은 서로 섞이지 않는다.

| 작업 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 원문 자막 생성 | 인식만 한다: 음성(위스퍼), 소리, 화면 글자 | LLM 분석, 교정, 번역 |
| 번역 자막 생성 | 원문 자막을 기준으로 번역한다(용어집 준비 포함 **[제안]**) | 검토, 원문 수정 |
| 자막 검토 | LLM이 고칠 곳을 찾아 티켓을 만든다 | 사람 승인 없는 "의심" 반영 |

사용자가 실제로 하는 순서:
1. 전체 원문 자막 생성을 요청한다. 트랙(화면, 음성, 소리)을 체크박스로 고른다.
2. 원문 검토를 요청하면 티켓이 생긴다. 티켓을 처리한다.
3. 전체 번역 자막 생성을 요청한다. 원문을 기준으로 번역된다.
4. 번역 검토를 요청하면 티켓이 생긴다. 티켓을 처리한다.
5. 보다가 이상한 곳은 구간·조각 검토를 한다. 원문을 보고 있으면 원문 검토, 번역을 보고 있으면 번역 검토다.

**재생성** **[결정]**
- 원문 자막이 있는데 전체 원문 생성을 요청하면, 고른 트랙의 기존 자막이 지워진다고 경고한다. 승인하면 그 트랙을 지우고 새로 만든다.
  - 지금의 "조각이 없는 구간만 채우기"는 없앤다.
  - 고르지 않은 트랙은 그대로 둔다.
- 번역 자막이 있는데 전체 번역 생성을 요청하면, 기존 번역이 다시 번역된다고 경고한다. 승인하면 전체를 다시 번역한다.
  - 옵션 "빈 칸만 채우기"를 두면 경고 없이 빈 칸만 번역한다 **[결정]**.
- 지운 조각에 걸린 티켓은 함께 지운다. 전체 재번역 때는 그 언어의 티켓을 지운다. 빈 칸 채우기 때는 지우지 않는다 **[제안]**.

**범위가 좁은 작업** **[제안]**: 구간·조각 칩의 "다시 받아쓰기", "화면 글자 찾기", "이 구간/조각만 번역"은 범위가 좁은 생성으로 남긴다. 구간·조각 칩에는 "검토" 버튼 하나를 더한다(7절).

## 3. 작품 원어 [결정, 세부는 제안]

- `ProjectState`에 `originalLanguage: Language`를 둔다. 새 프로젝트에서 묻는 "이 영상의 원문 언어"의 답이다.
- `CueSet.defaultLanguage`는 없앤다. 기본 언어를 쓰던 곳은 모두 작품 원어를 쓴다. 해당 기능:
  - 생성(받아쓰기, 화면 글자)과 검토
  - 번역 원문, 구간 작업
  - 빈 칸 대신 보이기, 출력 언어 기본값
  - 내보내기의 빈 칸 채우기("작품 원어로 채우기")
- 모든 자막셋은 작품 원어 칸을 늘 가지고, 그 칸은 뺄 수 없다. 다른 언어는 지금처럼 더하고 뺀다. "기본 언어로 정하기"는 없앤다.
- 작품 원어는 모든 자막셋에 조각이 하나도 없을 때만 바꿀 수 있다 **[결정]**. 바꾸면 각 자막셋의 `languages`에서 옛 원어를 새 원어로 바꾸고, 새 원어가 이미 있으면 옛 원어만 뺀다.
- 바꾸는 곳: 오른쪽 "자막셋" 탭 **[빌더: 정확한 자리]**. 조각이 있으면 이유를 도움말로 보이고 막는다.
- 자동 자막 생성 시트의 "만들 언어"는 고르는 칸을 없애고 작품 원어를 보여 주기만 한다.

## 4. 장면 메모 트랙 [결정, 세부는 제안]

**데이터**
- 메모는 자막셋에 속한다 **[결정]**: `CueSet.memos: [SceneMemo]`. 형태는 `SceneMemo { id, start, end (ms), text }`이다.
- 자막셋 복제에 함께 복제된다. 생성, 재생성, 구간 작업이 조각을 바꿔도 메모는 그대로다.
- 편집(추가, 시간 바꾸기, 글 고치기, 삭제)은 `SubtitleDataEditor`를 거쳐 실행 취소 한 단계씩이다.
- 메모는 언어와 상관없다. 사용자가 쓰는 말로 쓴다.

**화면**
- 타임라인에서 화면·음성·소리 아래에 "메모" 트랙을 둔다. 조각처럼 끌어 옮기고 양 끝을 늘린다.
- 빈 메모 트랙을 더블클릭하거나 조각 추가 메뉴의 "메모"로 만든다.
- 고르면 인스펙터에 시간과 글 칸이 보인다.
- 트랙 머리에는 눈과 휴지통이 있다.
- 메모끼리는 겹쳐도 된다 **[빌더: 겹칠 때 그리는 방식, 색]**.
- 구간·조각 칩의 "메모" 버튼: 그 시간으로 새 메모를 만든다. 겹치는 메모가 있으면 그 메모를 고른다.
- 내보내기, 조각 이동(⌘G 등), 조각 수, 겹침 검사, 번역 대상에 메모는 들어가지 않는다.

**LLM에 넣는 방식**
- 프롬프트의 "장면 메모" 칸에 `[00:03:41.0–00:03:58.0] 유리가 마사토에게 …`처럼 시간과 함께 넣는다.
- 보내는 줄의 시간 범위와 겹치는 메모만 넣는다. 전체를 보내면 모두 넣는다.
- 지침: 메모는 사용자가 직접 확인한 사실이니 작품 노트보다 우선한다.
- 메모가 들어가는 작업: 분석(노트 작성), 번역 생성, 원문 검토, 번역 검토.

## 5. 티켓 [결정, 세부는 제안]

### 5.1 데이터

```
Ticket
  id
  setID
  kind: source | translation          // 원문 검토에서 났는지, 번역 검토에서 났는지
  language: Language                  // 고칠 칸의 언어(원문이면 작품 원어)
  level: fix | suspect                // 고침 / 의심. LLM이 정한다 [결정]
  reason: String                      // 왜 고치는지(한국어)
  changes: [TicketChange]             // 1개 이상. 조각을 링크한다 [결정]
TicketChange
  cueID
  before: String                      // 티켓을 만들 때 그 칸의 문장
  after: String                       // 제안 문장
```

- 지금의 `CueMark`와 `CueMarkBook`, 검토 표시 관련 코드(ReviewList, ⌘G 의심 이동, 배지)는 티켓으로 바꾼다. 따로 두지 않는다.
- 티켓은 지금 표시처럼 `project.json`에 저장하고, 편집기가 자막 데이터와 함께 들고 있어 실행 취소 기록에 함께 들어간다.
- 티켓 하나는 언어 하나다. `changes`의 칸은 모두 `ticket.language` 칸이다 **[제안]**.
- 칸(조각×언어) 하나에는 열린 티켓이 하나까지다 **[제안]**. 검토가 이미 열린 티켓이 있는 칸에 대한 변경을 내면 버린다(남은 티켓은 프롬프트에 들어가니 지침으로도 막는다). 창으로 나눠 보낸 결과가 같은 칸에 겹치면 먼저 나온 것을 쓴다.
- 여러 조각을 링크하는 경우는 예를 들어 "앞뒤 두 줄의 주체가 바뀌어 같이 고쳐야 함"처럼 한 판단이 여러 줄에 걸칠 때다. 반영과 미반영은 티켓 단위다(조각별로 고르지 않는다).

### 5.2 고침과 의심 [결정]

| | 자막 칸의 문장 | 내보내기 | 반영 | 미반영 |
|---|---|---|---|---|
| 고침(fix) | `after`로 바꿔 둔다 | 고친 문장 | 티켓만 지운다 | 칸을 `before`로 되돌리고 티켓을 지운다 |
| 의심(suspect) | `before` 그대로 | 원래 문장 | 칸을 `after`로 바꾸고 티켓을 지운다 | 티켓만 지운다 |

- 티켓이 처리(반영 또는 미반영)되면 데이터를 지운다 **[결정]**.
- 편집 화면, 타임라인, 재생 오버레이는 칸의 지금 문장을 보여 준다. 고침은 고친 문장, 의심은 원래 문장이 보이고, 티켓 배지가 붙는다 **[제안]**.
- 사람이 티켓에 링크된 칸을 직접 고치면 그 티켓을 지운다. 판단 기준이 된 문장이 바뀌었기 때문이다 **[제안]**.
- 고침 문턱 **[제안]**: 지침에서 "고침은 문맥상 틀린 것이 분명하고 고친 문장이 하나로 정해질 때만" 쓰게 한다. 나머지는 모두 의심이다.

- LLM 작업(번역, 검토, 분석)이 보는 문장은 칸의 지금 문장이다. 고침 티켓이 열린 칸이면 `after`, 의심이면 `before`다. 내보내기와 같은 기준이다 **[제안]**.

### 5.3 원문이 바뀐 뒤 [제안]

원문 티켓이 처리되어 원문 칸의 최종 문장이 티켓을 만들기 전 문장(`before`)과 달라지면, 그 조각의 번역 칸 중 문장이 있는 칸마다 번역 티켓(의심)을 만든다. 의심을 반영했거나 고침을 반영한 경우다. 고침을 미반영하면 원래대로 돌아가니 만들지 않는다.
- 그 칸에 이미 열린 번역 티켓이 있으면 이 티켓으로 바꾼다(옛 원문을 기준으로 한 판단이기 때문이다).
- 티켓 처리와 이 티켓 생성은 실행 취소 한 단계다.
- 이유는 "원문이 바뀌었어요. 다시 번역이 필요할 수 있어요"이다.
- 제안 문장은 없다. `after`가 비어 있으면 반영 버튼은 "다시 번역"이 되어 그 조각만 번역한다 **[빌더: 버튼 이름]**.
- 사람이 원문을 직접 고친 경우에는 만들지 않는다.

## 6. LLM 작업

### 6.1 공통 [제안]

- 줄마다 시간(`mm:ss.s–mm:ss.s`), 종류(speech/screen/sound), 문장을 보낸다. 지침에서 "간격이 크면 장면이 바뀌었을 수 있다"고 알려 준다.
- 작품 노트와 겹치는 메모를 넣는다.
- 검토에는 그 범위에 남아 있는 티켓도 넣는다 **[결정]**. 이미 낸 판단을 다시 내지 않게 하고, 사람이 아직 처리하지 않았다는 것도 알려 준다.
- 전체를 보내는 작업은 기본으로 한 요청이다. 853줄 프로젝트가 노트까지 3만~4만 토큰이다.
- 요청이 문맥 길이 초과로 실패하면, 겹치는 창(예: 300줄, 앞뒤 50줄 겹침)으로 나눠 다시 보낸다. 로컬 프리셋(Ollama, LM Studio)은 처음부터 창으로 보내도 된다 **[빌더: 초과 감지, 창 크기]**.
- 구간·조각 검토는 대상 줄과 앞 10줄·뒤 5줄을 보낸다. 앞뒤 줄은 문맥이고 티켓 대상이 아니다.

### 6.2 작품 노트(분석) [결정, 세부는 제안]

- 노트가 없으면 첫 검토(원문이든 번역이든, 구간·조각 검토도) 전에 자동으로 만든다. 진행 단계는 "분석"으로 보이고, 취소하면 검토도 함께 멈춘다 **[제안]**.
- 노트 패널에는 노트만 새로 쓰는 버튼이 있다. 지금의 "다시 분석" 자리다.
- 분석은 원문 자막 전체와 메모를 본다.

### 6.3 번역 자막 생성 [제안]

- 나누기는 지금처럼 40~60줄이다. 문맥은 대상과 상관없이 자막셋 전체에서 고른다.
  - 앞 10줄과 뒤 5줄을 원문과, 그 줄에 있는 대상 언어 번역과 함께 보낸다.
  - "빈 칸만 채우기"와 "이 구간/조각만 번역"에서도 이웃 줄이 문맥이 된다. 이미 있는 번역은 고정된 문맥으로 보낸다.
- 지침에 더할 것:
  - 먼저 앞뒤 줄로 장면과 화자를 파악한다. 화자 이름은 노트의 인물표를 쓴다.
  - 생략된 주어와 목적어는 문맥으로 정한다.
  - 반복, 감탄, 감정 변화를 살린다.
  - 원문이 이상해도 원문대로 옮긴다(고치는 것은 원문 검토의 몫이다).
- 번역은 티켓을 만들지 않는다. 지금의 `ambiguous`와 번역 안의 검토 단계(일관성, 화면 확인, 자동 반영)는 번역에서 뺀다.
- 용어집 단계는 번역 준비로 번역에 남긴다.
- 문맥이 바뀌니 중간 저장 해시에 문맥 줄의 번역과 메모를 넣는다.

### 6.4 원문 검토 [결정, 세부는 제안]

- 목적: 위스퍼(와 화면 글자 인식)가 잘못 인식했을 법한 곳을 집중적으로 찾는다.
- 지침:
  - 음성 인식은 소리가 비슷한 다른 말로 적을 수 있다. 예: 명령형 おごれよ ↔ おごるよ, 조사, 활용 어미, 동음이의어, 인명.
  - 앞뒤 흐름, 메모, 화자 관계에 비춰 뜻이 맞지 않는 줄을 찾는다.
  - 말투, 문체, 띄어쓰기 취향은 바꾸지 않는다.
- 응답: 티켓 목록. 티켓마다 level, reason, 그리고 바꿀 줄과 바꾼 문장 목록이다.
- 전체 원문 검토와 구간·조각 원문 검토가 같은 지침을 쓴다.

### 6.5 번역 검토 [결정, 세부는 제안]

- 목적: 조각만 보면 맞는 번역인데 맥락상 잘못 이해한 곳을 찾는다.
- 보내는 것: 줄마다 원문과 대상 언어 번역, 노트, 메모, 남은 티켓.
- 대상 언어 하나에 한 요청이다.
- 찾을 것:
  - 화자나 행위의 주체를 반대로 잡은 곳
  - 생략된 말을 문맥과 다르게 채운 곳
  - 문맥상 뜻이 틀린 곳
  - 반복이나 감정 변화가 사라진 곳
  - 같은 인물 사이 말투 흔들림, 같은 표현의 다른 번역, 노트와 다른 표기
- 원문이 의심스러운 줄은 번역 티켓 대신 원문 티켓(의심, 제안 없음 가능)으로 낸다 **[제안]**.
- 용어집 검사(규칙 기반)는 번역 검토 요청 전에 돌린다. 그 결과("이 줄에 용어 X가 노트 표기 Y와 다름")를 프롬프트에 단서로 넣고, 티켓과 고친 문장은 LLM이 쓴다 **[제안]**.
- 애매한 조각의 화면 확인(비전 모델)은 번역 검토 안의 선택 단계로 둔다. 비전 모델이 있으면 의심 티켓 중 화면 글자와 관련된 것만 프레임을 보고 다시 판단한다 **[빌더: 고르는 기준]**.

## 7. 화면

**왼쪽 사이드바 = 티켓 패널** **[결정]**
- 자막셋 목록은 오른쪽 "자막셋" 탭으로 옮긴다.
- 작업 중 진행 기록은 지금처럼 사이드바 위쪽에 둔다 **[제안]**.
- 티켓 목록:
  - 원문/번역(언어별)과 고침/의심으로 거른다.
  - 행마다 level, 이유, 첫 조각의 시간이 보인다.
- 티켓을 고르면:
  - 링크된 조각으로 이동하고 고른다.
  - 패널에 조각별 diff(before → after)를 보여 준다.
  - [반영] [미반영] 버튼이 있다.
- 단축키: 다음/이전 티켓(지금 ⌘G 자리), 반영·미반영 **[빌더]**.

**구간·조각 칩** **[제안]**
- "검토" 버튼 하나를 둔다. 지금 출력 언어가 작품 원어(또는 "전체")면 원문 검토, 번역 언어면 그 언어의 번역 검토다.
- "메모" 버튼을 더한다.
- 버튼이 많아 칩이 넘치면 작업 버튼을 메뉴로 묶어도 된다 **[빌더]**.

**생성 시트**
- 원문 생성: 트랙 체크박스(화면, 음성, 소리). 고른 트랙에 조각이 있으면 지운다고 경고한다.
- 번역 생성: 대상 언어, "빈 칸만 채우기" 옵션. 번역이 있고 옵션이 꺼져 있으면 다시 번역된다고 경고한다.
- 검토 요청: 제목 막대나 메뉴에 "원문 검토", "번역 검토(언어)"를 둔다 **[빌더: 위치]**. 지금의 "교정" 버튼은 "원문 검토"가 대신한다.

## 8. 확인 방법 [제안]

- 실제 확인은 1절의 장면으로 사용자가 직접 한다. 구현 중에는 OpenAI를 부르지 않는다(사용량은 사용자 몫이다).
  - 원문 검토가 じゃあ飯をおごるよ에 티켓을 내면 성공이다.
  - 번역 검토가 이 장면의 주체·흐름 오류에 티켓을 내면 성공이다.
- 자동 테스트는 가짜 LLM으로 한다:
  - 프롬프트에 들어가는 줄, 메모, 남은 티켓
  - 요청 수(전체는 한 번, 초과 시 창)
  - 티켓 반영·미반영의 칸 변화와 내보내기 결과
  - 재생성 때 티켓과 메모의 처리
  - 작품 원어 변경 막힘
