# Jamak 3단계: LLM 분석·교정·번역·검증 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 원문 자막셋을 LLM으로 분석·교정하고, 다른 언어로 번역하고, 번역을 검증한다. 의심·자동 수정 표시는 편집기에서 검토한다. 작품 노트(`notes.md`)를 보여주고 고칠 수 있게 한다.

**Architecture:** 네 층으로 나눈다.
- **`JamakCore`**: 순수 로직과 파이프라인 조율. LLM은 `ChatCompleting` 프로토콜로 주입받는다. 그래서 가짜 클라이언트로 빠르게 테스트할 수 있다.
  - 구간 나누기, 응답 JSON 파싱, 구간 중간 저장
  - 작품 노트 읽기·쓰기·병합
  - 분석, 교정, 용어집, 번역, 번역 검증 파이프라인
  - 의심 표시 장부(`AnnotationBook`), 원본·번역 짝짓기
- **`JamakLLM`**: 같은 패키지의 새 타깃. OpenAI 호환 Chat Completions 클라이언트(URLSession)다.
- **앱**: 설정(프로바이더, Keychain), 단계 실행과 진행 UI, 노트 패널, 검토 UI를 맡는다.

**Tech Stack:** Swift 6.4, SwiftUI/AppKit, URLSession, Security(Keychain), CryptoKit, Swift Testing

**Spec:** `docs/superpowers/specs/2026-11-05-jamak-design.md`. 범위는 다음과 같다.
- 3장 LLM 설정
- 4.5 작품 노트, 4.6 자막셋 관계(짝짓기, 시간 맞추기, 이 구간만 번역), 4.7 의심 표시 저장
- 5.1 툴바(교정, 번역, 작품 노트), 5.4 검증·교정 표시
- 6.2 분석, 6.3 교정, 7 번역 파이프라인, 8 LLM 호출 공통

## Global Constraints

- macOS 14 이상, Apple Silicon, App Sandbox를 유지한다. `network.client`는 이미 있다.
- Info.plist에 `NSAppTransportSecurity` → `NSAllowsLocalNetworking = true`를 넣는다. localhost나 LAN의 http 서버(Ollama, LM Studio)를 쓰기 위해서다.
- **LLM 호출**
  - OpenAI 호환 `POST {baseURL}/chat/completions`, 모델 목록은 `GET {baseURL}/models`다.
  - API 키가 있으면 `Authorization: Bearer <키>`를 보낸다.
  - `response_format: {"type":"json_object"}`를 먼저 보낸다. HTTP 400이 오면 그 클라이언트에서는 빼고 다시 보낸다.
  - 요청 제한 시간은 300초다.
  - temperature는 번역 0.3, 그 밖의 단계 0.2다.
  - 이미지는 `{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,…"}}`로 보낸다.
- **프로바이더 프리셋** (base URL)
  - Ollama `http://localhost:11434/v1`
  - LM Studio `http://localhost:1234/v1`
  - OpenAI `https://api.openai.com/v1`
  - 직접 입력
- **설정 저장**: `UserDefaults` 키 `llmSettings`에 JSON으로 둔다. API 키는 Keychain(service `Jamak.LLM`, account = 프로바이더 UUID 문자열)에 둔다.
- 동시 요청 수는 기본 2, 범위 1~8이다.
- **구간 나누기**: 문장 40~60개, 목표 50개다. 앞 구간 끝 5문장을 맥락으로 함께 넘긴다.
- **LLM에 넘기는 조각 id**는 자막셋을 타임라인 순서로 정렬했을 때의 1부터 시작하는 순번 문자열이다(`"1"`, `"2"` …). UUID는 넘기지 않는다.
- **응답 처리**
  - 빠진 id나 모르는 id가 있거나 JSON이 깨졌으면 그 구간을 최대 2번 더 보낸다. 시도마다 맞게 온 줄은 모아 둔다.
  - 끝내 못 받은 조각은 원문 그대로 두고 의심 표시(이유: "LLM 응답을 받지 못했어요")를 단다.
  - 연결 실패나 HTTP 4xx(400 json_object 재시도 제외)는 단계 전체를 실패로 끝낸다. HTTP 5xx와 시간 초과는 재시도 대상이다.
- **구간 중간 저장**: 프로젝트 폴더 `work/<단계>-<언어>/<구간 번호 4자리>.json`에 둔다.
  - 구간 입력(순번, 종류, 본문)의 SHA-256을 함께 저장한다. 해시가 다르면 버린다.
  - 단계가 끝나면 그 폴더를 지운다.
- **화면 검증 프레임**: 조각의 시작 초, 가운데 초, `(end-1)/1000` 초에서 중복을 뺀 최대 3장을 쓴다. 캐시에 있는 파일만 쓴다.
  - 프레임이 하나도 없거나 비전 모델이 설정되지 않았으면 화면 검증을 건너뛴다. 이때 의심 표시는 LLM의 이유로 남는다.
- **종류 부호**: LLM에는 부호를 뺀 본문과 종류(`speech`/`sound`/`screen`)를 따로 넘긴다.
  - 받은 본문이 그 종류의 부호(`[]`, `［］`, `「」`, `{\an8}`)로 전체가 감싸져 있으면 벗긴다. 앞뒤 공백도 지운다.
  - 빈 문자열은 응답이 빠진 것으로 본다.
- **교정 대상**은 음성과 화면 조각이다. 소리 조각은 고치지 않는다. 번역 대상은 세 종류 모두다.
- **적용 정책**
  - "전체 자막 생성" 안에서 처음 하는 교정은 결과를 자동 적용한다. 바뀐 조각에는 `autoFixed`(`previousText` = 원래 문장)를 단다.
  - 툴바 "교정"으로 다시 하면 자동 적용하지 않는다. `suspect`(`suggestion` = 제안 문장)만 단다.
  - 번역 파이프라인의 검증 결과는 새로 만든 번역 자막셋에 자동 적용한다(`autoFixed`). 메뉴 "번역 검토 다시 하기"는 제안만 단다.
- **작품 노트**: 프로젝트 폴더 `notes.md`다. 번역 섹션 제목은 `## 번역: <언어 이름>`이다(예: `## 번역: 한국어`). 언어 이름은 `Locale(identifier: "ko_KR").localizedString(forLanguageCode:)`로 얻는다.
- **분석 입력**: 원문 줄을 `[HH:MM:SS] 본문` 형식으로 쓰고, 12,000자 단위로 나눈다. 구간이 둘 이상이면 구간별 결과를 합친다.
- **프롬프트**는 `JamakCore/Resources/Prompts/<이름>.txt`다. `{{키}}` 자리 표시자를 쓴다. 문구는 빌더 재량이지만, 응답 JSON 모양은 아래 각 작업에 적힌 대로 고정한다.
- **UI 문구**는 한국어이고 동작을 그대로 말한다.
  - 툴바: "교정", "번역"(언어 메뉴), "작품 노트"
  - 메뉴: "분석 다시 하기", "번역 검토 다시 하기", "원본 자막셋 시간에 맞추기", "다음 의심 조각"(⌘G), "이전 의심 조각"(⇧⌘G)
  - 구간 바: "이 구간만 번역"
  - 편집 패널: "제안으로 바꾸기", "그대로 두기", "원래 문장으로 되돌리기"
  - 설정 탭: "LLM", 버튼 "연결 확인"
- **무거운 작업**은 메인 액터 밖에서 돈다. 단계마다 진행률("구간 n/m"), 취소, 실패 후 그 단계부터 재개를 지원한다.

## Review Focus

1. **긴 작업 중간에 LLM 서버가 죽거나, 모델 이름이 틀리거나, 앱을 끈 경우**
   - 단계 이름과 읽을 수 있는 이유로 실패한다. 예: "교정에 실패했어요: LLM 서버에 연결할 수 없어요 (http://localhost:11434/v1)"
   - 다시 실행하면 끝난 구간을 다시 보내지 않는다.
   - → Task 1 `checkpointSkipsDoneChunks`, Task 6 `resumesAfterServerFailure`
2. **LLM이 JSON을 깨뜨리거나, id를 빠뜨리거나, 없는 id를 만들거나, 부호를 붙여 돌려주는 경우**
   - 재시도한 뒤 원문을 유지하고 의심 표시를 단다. 본문이 다른 조각에 들어가거나 부호가 두 번 붙는 일은 없어야 한다.
   - → Task 1 `stripsKindMarkupFromReply`, Task 8 `missingIdsRetriedThenKeptAsSource`
3. **사용자가 원문을 손으로 고친 뒤 "교정"을 다시 누른 경우**: 본문은 바뀌지 않고 제안만 생긴다. → Task 6 `rerunOnlySuggests`
4. **사용자가 쓴 notes.md가 있는 경우** (열 순서가 다른 표, 빈 칸, 표 밖의 자유 서술): 분석 후에도 사용자 내용이 그대로 남고, 새 행만 늘어난다. → Task 4 `mergeKeepsUserRowsAndProse`
5. **이미 손으로 고친 번역 자막셋이 있는데 같은 언어로 다시 "번역"한 경우**: 덮어쓸지 묻는다. 취소하면 아무것도 바뀌지 않는다. → Task 12 수동 검증

**Interfaces:**

  ```swift
  public enum ChatPart: Equatable, Sendable { case text(String), imageJPEG(Data) }
  public struct ChatMessage: Equatable, Sendable {
    public enum Role: String, Sendable { case system, user, assistant }
    public var role: Role; public var parts: [ChatPart]
    public static func system(_ s: String) -> ChatMessage
    public static func user(_ s: String, images: [Data] = []) -> ChatMessage
  }
  public struct ChatRequest: Equatable, Sendable {
    public var model: String; public var messages: [ChatMessage]
    public var temperature: Double; public var wantsJSON: Bool = true
  }
  public protocol ChatCompleting: Sendable {
    func complete(_ request: ChatRequest) async throws -> String
  }
  public enum LLMError: Error, Equatable {
    case unreachable(String)           // base URL
    case http(status: Int, message: String)
    case timedOut
    case badReply(String)               // 파싱·검증 실패, 재시도 대상
    var isRetryable: Bool               // http 5xx, timedOut, badReply
  }
  public enum JSONReply {
    /// 코드 펜스를 벗기고, 첫 `{`부터 짝이 맞는 `}`까지를 디코드한다. 실패하면 LLMError.badReply.
    public static func decode<T: Decodable>(_ type: T.Type, from text: String) throws -> T
    /// 종류 부호로 전체가 감싸진 본문이면 벗기고 앞뒤 공백을 지운다.
    public static func cleanText(_ text: String, kind: SubtitleKind) -> String
  }
  public struct Chunk: Equatable, Sendable {
    public var index: Int
    public var items: Range<Int>        // 정렬된 조각 배열의 범위
    public var context: Range<Int>      // 앞 구간 끝 최대 5개
  }
  public enum ChunkPlanner {
    /// 40~60개 범위에서 이웃 조각 사이 간격이 가장 큰 곳에서 자른다. 남은 수가 60 이하면 한 구간으로 끝낸다.
    public static func plan(_ clips: [SubtitleClip], target: Int = 50, min: Int = 40, max: Int = 60, context: Int = 5) -> [Chunk]
  }
  public struct CheckpointStore: Sendable {
    public init(folder: URL)
    public static func hash(_ lines: [String]) -> String          // SHA-256 hex
    public func load<T: Decodable>(_ type: T.Type, chunk: Int, hash: String) -> T?
    public func save<T: Encodable>(_ value: T, chunk: Int, hash: String) throws
    public func clear() throws
  }
  public enum ChunkRunner {
    /// 구간을 동시에 최대 `limit`개 돌리고 입력 순서대로 결과를 돌려준다.
    /// `attempt`가 retryable 오류를 던지면 최대 2번 더 부른다(그 사이 부분 결과는 `attempt`가 스스로 모은다).
    /// 끝내 실패한 구간은 nil. 재시도할 수 없는 오류와 취소는 바로 던진다.
    /// `onProgress(끝난 구간 수, 전체)`는 구간이 끝날 때마다 부른다(중간 저장에서 불러온 구간 포함).
    public static func run<T: Sendable>(_ chunks: [Chunk], limit: Int,
        attempt: @Sendable @escaping (Chunk, _ try: Int) async throws -> T,
        onProgress: @Sendable @escaping (Int, Int) -> Void) async throws -> [T?]
  }
  public enum Prompts {
    public static func text(_ name: String, _ values: [String: String] = [:]) throws -> String
    static func fill(_ template: String, _ values: [String: String]) -> String   // text가 쓰는 치환
  }
  ```
  - `FakeChat`(테스트 지원): 요청을 기록한다. 순서대로 돌려줄 응답이나 오류 목록, 또는 요청 → 응답 클로저를 받는다.
- 중간 저장은 `ChunkRunner`가 아니라 각 파이프라인이 `attempt` 안에서 `CheckpointStore`로 한다.

- [ ] **Step 1: 실패하는 테스트**
  - `decodesFencedJSON`: ```` ```json\n{"a":1}\n``` ```` → 디코드
  - `decodesJSONAfterProse`: `"네, 결과입니다: {\"a\":1} 끝"` → 디코드
  - `brokenJSONIsBadReply`
  - `stripsKindMarkupFromReply`
    - sound `"[銃声]"` → `"銃声"`, sound `"［銃声］"` → `"銃声"`
    - screen `"{\\an8}「出口」"` → `"出口"`, screen `"「出口」"` → `"出口"`
    - speech `"「待て」と言った"` → 그대로
    - 앞뒤 공백을 지운다.
  - `plansSingleChunkForSmallSet`: 30개 → 구간 1개, context 비어 있음
  - `plansChunksWithinBoundsAtLargestGap`
    - 130개, 간격은 모두 1000ms이고 i=47 뒤만 5000ms → 첫 구간은 0..<48이다.
    - 모든 구간이 40~60 범위에 있다. 단, 마지막 구간은 40 미만일 수 있다.
    - 범위를 이어 붙이면 0..<130이다.

- Modify: `App/Jamak/Generation/LLMStages.swift`, `EditorView.swift`(툴바 번역 메뉴), `RangeBar.swift`, `JamakApp.swift`(메뉴), `AppModel.swift`

**Interfaces:**
- Consumes: Task 8, 9, 10, 11
- 동작
  - **툴바 "번역"** 메뉴: 한국어 / 영어 / 일본어 / 중국어(간체) 중 원본(활성 자막셋)과 다른 언어
    - 대상 언어 자막셋이 이미 있고 진행이 완료 상태이거나 없으면 묻는다.
      - 제목: "번역 자막을 새로 만들까요?"
      - 내용: "지금 <언어> 자막셋을 덮어써요. 손으로 고친 내용은 사라져요."
      - 버튼: "새로 만들기"/"취소"
      - 취소하면 아무것도 바뀌지 않는다.
    - 진행이 미완료면(같은 원본 언어) 묻지 않고 이어서 한다.
    - 순서
      1. 용어집: 노트 `## 번역: <언어>`에 병합하고 저장한다. `glossaryDone`
      2. 번역: 조립한 자막셋과 표시를 저장한다(`applyGenerated`). `translated`
      3. 번역 검토: 용어집 검사 + 일관성 + 화면 확인(애매함 조각, 비전 모델이 있을 때). 그다음 `ReviewApplication.apply(autoApply: true)`로 적용하고 저장한다. `reviewed`
    - 번역 단계의 애매함 이유는 `TranslationOutcome.ambiguous`를 `work/translate-<언어>/ambiguous.json`에 둔다. 검토 단계를 따로 재개할 때도 쓰기 위해서다.
    - 원본은 시작할 때의 스냅숏이다(저장 확인을 거친다). 대상 언어 자막셋을 잠근다.
    - 끝나면 대상 언어 자막셋으로 전환하지 않는다. 완료 알림에 "<언어> 자막셋 열기" 버튼을 둔다.
  - **메뉴 "번역 검토 다시 하기"**
    - 활성 자막셋이 번역(`translations[활성 언어]`가 있음)일 때만 켠다.
    - 원본은 `translations[활성].sourceLanguage` 자막셋이다.
    - 용어집 검사와 일관성만 돌린다(애매함 기록이 없으므로 화면 확인은 하지 않는다). `autoApply: false`
  - **구간 바 "이 구간만 번역"**
    - 활성 자막셋이 원본일 때, 대상 언어는 프로젝트에 있는 다른 언어 자막셋 중 고른다. 없으면 비활성이고 도움말은 "먼저 '번역'으로 번역 자막셋을 만드세요"다.
    - `ClipPairing.rangeTranslation`으로 지울 것과 번역할 것을 정한다.
    - 노트의 해당 언어 용어집을 그대로 쓴다(용어집 단계 없음). 결과는 `assemble`로 만든다.
    - 대상 자막셋에 실행 취소 한 단계로 넣는다. 대상이 활성이 아니면 저장한다.
    - 화면 검증은 하지 않는다. 애매함은 suspect로 단다.
  - **메뉴 "원본 자막셋 시간에 맞추기"**: 활성 자막셋이 번역일 때, 원본과 짝지어진 조각의 시간을 맞춘다(실행 취소 한 단계).
